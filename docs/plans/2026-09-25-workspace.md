# 오피스 안의 코드·터미널·이동

사용자가 레포별 오피스를 보면서 코드를 읽고 셸 명령을 실행하고, 에이전트가 작업 종류에 맞는 공간으로 이동하는 모습을 확인한다. 기존 추천 방식으로 계속 진행하라는 요청에 따라 구현한다.

- 작업 공간: 현재 선택한 레포 또는 앱 실행의 분리된 작업 폴더를 명시적으로 선택한다. 파일 탐색기는 읽기 전용, 텍스트 미리보기와 줄 번호, 새로고침을 제공한다. 등록/관측된 루트만 허용하며 경로 탈출, 심볼릭 링크, 바이너리와 큰 파일은 차단한다.
- 터미널: xterm.js와 node-pty로 실제 대화형 셸을 연다. 사용자가 시작 버튼을 눌러야 생성한다. 입력, Ctrl+C, 화면 크기 변경, 종료와 재연결을 제공한다. 로그인 쿠키와 동일 출처 검증을 HTTP/WS 양쪽에 적용한다. 세션은 레포별로 격리하며 패널을 숨겨도 유지하고, 연결 없는 터미널은 5분 뒤 정리한다. 서버 종료 시 모두 종료한다. 터미널은 로컬 사용자 권한의 셸이며 파일을 변경할 수 있다.
- 맵: 기존 세션별 캐릭터 선택과 채팅을 유지한다. 자료 확인→자료 공간, 코드 작성→책상, 명령 실행→테스트 공간, 검토·응답→협업 공간, 완료→휴식 공간. 상태가 바뀔 때 이동하며 무작위 이동으로 작업을 꾸미지 않는다. 오래된 관측은 상태 확인 필요로 표시한다. 모바일에서도 캐릭터가 겹치지 않는 슬롯과 이동 줄이기 설정을 제공한다.

구현 순서: 파일 API/PTY 수명주기 및 인증 → 코드·터미널 패널 → 상태 기반 맵 이동 → 단위/API/실제 PTY/데스크톱·모바일 E2E → 문서와 GitHub 반영.

검증: 경로 탈출·심볼릭 링크·대형/바이너리 거부, 등록하지 않은 루트 거부, WS 외부 출처·미인증 거부, 실제 셸 cwd/입력/중단/재연결/종료, 빠른 레포 전환 시 데이터 격리, 상태 변경 시 좌표 변화, 이동 줄이기, 채팅 회귀, 화면 넘침.
