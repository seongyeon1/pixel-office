# 외부 세션 관측

요청: 이미 터미널·IDE에서 실행 중인 Claude Code와 Codex 세션을 자동으로 찾아 레포별 활동을 보여준다.

## 구조

- 서버 시작 시 Codex `sessions/**/*.jsonl`, Claude `projects/**/*.jsonl`을 읽기 전용으로 탐색한다. `CODEX_HOME`, `CLAUDE_CONFIG_DIR`을 지원한다.
- 최근 7일에 변경된 파일과 열린 세션의 후보를 합쳐 최대 200개를 관측한다. Claude의 생존 PID 세션과 Codex writer-lock 파일의 세션을 먼저 포함한다. lock 존재 자체를 실행 여부로 표시하지는 않는다. 10초 간격으로 새 파일을 발견하고 2초 간격으로 추가된 로그를 읽는다.
- 세션 ID와 로그 파일 경로로 안정적인 관측 식별자를 만든다. Git worktree의 원래 저장소 경로로 묶고 실제 작업 폴더도 별도 표시한다.
- 관측 세션은 앱 실행 기록과 별도 타입·API를 사용한다. 외부 세션에 취소·승인·재실행 요청을 보내지 않는다. 앱이 만든 작업 폴더는 제외한다.
- 레포 선택기에 외부 세션 수를 표시하고 오피스에서 세션별 최근 메시지와 도구 활동을 확인한다. 외부 관측과 앱 작업 사이를 전환할 수 있다.
- 처음 읽을 때 로그 앞부분 128 KiB와 끝부분 512 KiB만 읽고, 이후에는 추가된 바이트를 추적한다. 부분 기록·잘못된 JSON·파일 축소·교체에 대응한다.
- 최근 이벤트 80개만 메모리에 보관한다. 원본 로그, 시스템 지침, reasoning/thinking, 전체 도구 출력은 데이터베이스에 복제하지 않는다.

## 상태의 의미

- **활동 관측**: 완료 이벤트 뒤에 시작·메시지·도구 기록이 관측되었고 마지막 활동이 2분 이내다. 프로세스 실행 확정 표시가 아니다.
- **응답 완료·대기**: 로그에서 해당 응답의 완료를 관측했다. 전체 세션 종료를 뜻하지 않는다.
- **상태 확인 필요**: 최근 이벤트가 없거나 진행 중으로 보인 뒤 2분 이상 새 기록이 없다. 긴 명령이나 승인 대기일 수도 있다.
- Claude의 세션 레지스트리가 제공되면 PID 생존 여부도 별도로 표시한다. 실행 중이라는 사실과 현재 작업 상태를 구분한다.

로그가 기록되지 않는 세션, 다른 컴퓨터·컨테이너의 세션은 해당 로컬 로그 경로 없이는 표시할 수 없다. 세션 로그 형식은 공급자 버전에 따라 달라질 수 있으며, 알 수 없는 레코드는 건너뛴다.

## 근거와 검증

- Claude 세션 저장 위치: [공식 세션 문서](https://code.claude.com/docs/en/sessions).
- Codex 설정과 저장 경로: [공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference). 상세 이벤트 파서는 설치된 Codex 0.156.1과 Claude Code 2.1.282의 로컬 로그 구조를 확인해 구현했다.
- 합성 로그를 사용해 증분 기록·부분 행·worktree 묶음·상태 노후화·파일 축소·관리 작업 제외·잘못된 기록과 누락 경로를 검증한다.
- 브라우저에서 기존 세션 자동 발견, 도구 내용, 로그 추가 반영, 세션 전환, 모바일 너비와 관측 전용 동작을 검증한다.
