2026-09-25, macOS arm64, Node.js 24.7.0 환경에서 확인했습니다.

- 단위·서버 통합 테스트: 이벤트 재생, 승인 중복 응답 차단, 서버 재시작 상태, Git worktree 격리, 한글 파일명, 심볼릭 링크 표시, 최초 커밋 누락, 공급자 이벤트 정상화, RPC 분할 입력·종료, 검토 횟수 제한, 페르소나 전달, 취소-완료 경합, HTTP 출처·인증, UI 이벤트 중복 제거, 모델 목록.
- 브라우저 E2E: 데스크톱 1440×1000 및 모바일 390×664에서 모델·직급 설정, 화면 너비, 승인 대기 중 새로고침, 질문 응답, 구현→검토 인계, 변경 파일 diff, 작업 중단, 세션 만료 안내, 단독 실행 역할 표시.

- GitHub Actions에서 단위·타입·빌드·브라우저 검증을 반복하도록 구성했습니다. 실제 유료 공급자 실행은 CI에 포함하지 않습니다.

## 실제 공급자 실행

Codex CLI 0.156.1, Claude Code 2.1.282, Claude Agent SDK 0.3.282로 샘플 Git 프로젝트를 실행했습니다.

**Codex 구현 → Claude 검토 협업**이 완료됐습니다. 샘플의 `add(a,b)`를 고치고 Claude가 `node --test`로 확인한 뒤 pass 판정을 반환했습니다. 하네스가 독립적으로 재실행한 테스트도 통과했고 원본 저장소의 파일은 바뀌지 않았습니다. 일부 읽기 명령이 하네스의 제한된 승인 목록에 없어 거절된 사실은 검토 결과에 그대로 남았습니다.

검증 중 발견해 수정한 사항:

- macOS의 `/var`와 `/private/var` 경로 차이로 발생한 파일 포함 범위 판정 오류.
- Claude 구조화 출력에서 지원되지 않은 JSON Schema draft. 두 공급자 모두 지원하는 draft-07로 변경.
- 모바일에서 동료 선택 버튼과 모델 정보가 숨겨지는 문제. 모바일 동료 선택 영역과 모델 정보를 추가.

## 관측 범위와 제한

- 실제 연동은 현재 macOS에서 확인했습니다. Linux·Windows의 CLI 인증과 샌드박스 동작은 추가 검증이 필요합니다.
- SQLite는 사용한 Node.js 버전에서 experimental 경고를 출력하지만 저장·복원 테스트는 통과했습니다.
- 작업 출력은 관측 가능한 메시지와 도구 실행을 기반으로 표시합니다. 모델의 내부 사고를 추정하지 않습니다.
- 직급은 역할 지침입니다. 자동 벤치마크나 성능 순위는 제공하지 않습니다.
- 개발·브라우저 테스트에서 사용한 데모 공급자는 테스트 전용 서버에만 있으며, 실제 앱 연결 실패를 데모로 대체하지 않습니다.
- 승인 거절, 검토 불확실성, 수정 횟수 소진은 성공으로 표시하지 않습니다.

- `npm test`: **31개 통과**.

- `npm run build`: 통과.

- 실제 Claude 단독 구현: 완료, 수정 승인·명령 승인 후 샘플 테스트 통과, 원본 보존 확인.
- 두 공급자의 실제 모델 카탈로그 조회: 성공.

독립 코드 검토에서 발견한 Important 3건은 실패하는 회귀 테스트를 만든 후 수정했습니다.

1. `*.txt`, `:(invalid)file.txt` 같은 경로를 Git pathspec이 아닌 literal 파일명으로 처리.
2. 10 MB 파일 삭제·축소 시 기준 커밋의 blob 크기를 확인해 제한된 생략 안내 반환.
3. 서버 재시작 후 세션 만료를 인식하고 새 연결 URL 안내 표시. 정상 재접속 시 snapshot 재조회, interrupted 이벤트 반영.

추가로 단독 실행에서 실제 구현 담당자와 작업 단계가 정확히 표시되도록 수정하고 데스크톱·모바일 회귀 테스트를 통과했습니다.

검토자는 과금이 발생하는 실제 공급자 실행을 반복하지 않았습니다. 이 항목은 구현 세션에서 별도로 수행한 위 smoke 검증을 근거로 합니다. 강제 종료의 모든 OS·하위 프로세스 조합을 검증한 것은 아닙니다.

실행 결정: 기존 코드가 없는 폴더여서 요청한 경로에 새 Git 저장소와 기능 브랜치를 만들었습니다. 기존 작업을 덮어쓰지 않으며 별도 기본 checkout은 생성하지 않았습니다. 원격 저장소도 비어 있어 완성된 초기 버전을 `main`에 게시합니다.

## 레포 코드·실제 터미널·활동별 이동

- 파일 API: 등록된 레포/관측 레포/기록된 앱 worktree만 허용한다. 경로 탈출, 심볼릭 링크 파일과 폴더, 환경변수 파일, 바이너리, 잘못된 UTF-8, 256 KB 초과와 디렉터리 입력을 거부했다. 빈 파일, 크기 경계, 변경 후 다시 읽기와 디렉터리 정렬을 검증했다.
- 터미널: 실제 `/bin/sh` PTY로 cwd, 대화형 `read`, resize 후 `stty size`, `cd` 후 재연결, 출력 재생, 긴 명령의 Ctrl+C와 `exit`를 확인했다. 미연결 세션 만료와 명시적 종료도 검증했다. HUP를 무시하는 셸은 강제 종료까지 확인한다.
- 보안: 파일/터미널 HTTP 인증, 외부 Origin과 등록되지 않은 루트 거부, WS 미인증·외부 Origin·Origin 누락 거부, 잘못된 resize와 정상 WS 연결/종료를 검증했다.
- 브라우저: 데스크톱/모바일에서 파일 탐색, 실제 키 입력, Ctrl+C, 패널 재열기, 레포 전환 시 파일/터미널 분리, 원래 셸 재연결과 종료를 확인했다. 터미널 코드는 패널을 열 때 지연 로드한다.
- 이동: 활동 변경에 따라 실행 공간에서 휴식 공간으로 좌표와 실제 이동 상태가 바뀌고, 도착 후 선택과 채팅이 유지됨을 확인했다. 8명 좌표 중복과 순서 변경 시 불필요한 이동을 단위 테스트로 검사하고 브라우저에서 이동 줄이기 설정을 검증했다.
- 설치: macOS node-pty 1.1.0의 `spawn-helper` 실행 권한 누락을 최소 PTY 재현으로 확인하고, 설치 후 해당 파일의 사용자 실행 비트만 보정한다. E2E는 개인 셸 설정을 읽지 않는 `/bin/sh`를 사용한다.
- 합성 fixture 화면은 `docs/images/workspace-{code,terminal}-{desktop,mobile}.png`와 `session-chat-{desktop,mobile}.png`에 보관한다. 실제 공급자 작업 호출은 이 변경의 검증에 필요하지 않다.

## 전체 프로젝트 맵

- 절대 경로를 기준으로 연결된 프로젝트와 외부 세션을 합친다. 같은 이름의 폴더 구분, 비어 있는 프로젝트, 활동/대기/관측 지연 집계, 앱 작업 담당자와 승인 우선 표시, 완료된 앱 작업의 캐릭터 제외를 단위 테스트로 검증했다.
- 데스크톱·모바일에서 두 `shared` 프로젝트와 빈 프로젝트를 함께 표시하고, 4명 표시 제한·추가 인원 안내·경로 구분·검색·활동 필터·새로고침 복원을 확인했다.
- 네 번째 외부 캐릭터 선택이 정확한 세션을 여는지, 로그에 작업 완료를 추가하면 실시간으로 대기 상태가 되는지 확인했다. 앱 작업 캐릭터는 외부 세션과 섞이지 않고 해당 작업의 승인 화면으로 연결됐다.
- 동시 작업 중인 다른 개발 세션의 테스트 서버와 충돌하지 않도록 별도 임시 복사본과 4418 포트에서 검증했다. 이 복사본에는 당시 작업 폴더의 맵 이동 개선도 포함됐다. 타입 검사·빌드, 단위 테스트 **45개**, 브라우저 테스트 **22개**가 통과했다.
- `project-map-desktop.png`, `project-map-mobile.png`는 합성 세션으로 생성한 화면이다. 실제 사용자 로그나 대화는 저장소에 추가하지 않았다.

## 오피스 가구·상태 말풍선 반영 및 화면 재확인

- 코드 작업·자료·테스트·휴식 구역에 고정 가구를 배치하고, 캐릭터 좌표와 가구 좌표를 같은 계산으로 맞췄다. 가구 앞뒤 레이어 사이에 캐릭터를 표시하며 상태 말풍선과 이름표를 분리했다. 모든 캐릭터에 대응하는 자리가 존재하는지 단위 테스트로 확인했다.
- 최신 소스로 타입 검사·빌드와 단위 테스트 45개를 다시 통과했다. 외부 세션 감지·활동 변경에 따른 이동·캐릭터 선택·채팅·새로고침을 데스크톱/모바일 브라우저 테스트 2개로 확인하고 합성 화면을 갱신했다.
- 화면 장애 제보 후 4317 서버의 HTML·JS·CSS 응답과 새 연결 URL을 점검했다. 서버는 실행 중이었고 실제 브라우저에서 전체 맵과 외부 세션 오피스가 정상 렌더링되어 장애는 재현되지 않았다. 최신 빌드를 다시 생성해 제공했으며 실행 중인 작업을 끊는 서버 재시작은 하지 않았다.
