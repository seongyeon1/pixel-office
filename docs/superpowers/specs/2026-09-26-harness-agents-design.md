# 개인 하네스 에이전트와 협업 실행 구조

## 요구사항과 현재 구현

사용자는 Claude는 `sy`, Codex는 `syc`로 새 에이전트를 시작하고, 에이전트 간 협업으로 확장하기를 원한다.
로컬 실행 파일을 확인했다. `sy`는 BrainCrew 플러그인을 지정하고, `syc`는 개인 Codex 설정으로 CLI를 실행한다.
둘 다 평소 사용자가 지정한 권한 옵션을 적용한다.

현재 구현한 진입점은 프로젝트의 **새 동료 → 공급자 / 개인 하네스 또는 기본 CLI → 처음 맡길 일 → 동료 시작**이다.
선택한 프로젝트 폴더에서 새 대화형 CLI를 실행한다. 앱 작업의 별도 worktree 생성과는 다른, 표시된 폴더에 직접
작업하는 진입점이다. 원래 하네스의 플러그인, 훅, 설정, 권한을 유지한다.

`LaunchedAgent`는 동료 ID, 공급자, 하네스, 폴더, 최초 요청, 터미널 ID, 생성 시각을 가진다.
`launcher.ts`가 명령 구성과 생성 중복 방지를 담당하고, `terminals.ts`가 프로세스 수명과 입출력을 담당한다.
API는 연결된 폴더만 허용하고 요청 본문으로 실행 파일이나 셸 코드를 받지 않는다. 프롬프트는 하나의 인자로 인용한다.
탭을 숨기거나 브라우저를 새로고침해도 서버의 실행을 찾아 연결한다. 서버 재시작 시 프로세스는 종료된다.
Claude는 동료 ID를 세션 ID로 전달한다. Codex의 CLI 세션 ID는 CLI가 생성하며, 현재 동료 ID와 별개다.

## 협업 계층의 확장 지점

현재 자동 협업은 `orchestrator.ts`의 구현 → 검토 → 수정 흐름이다. 이 실행은 Claude SDK / Codex app-server를
사용하며, 사용량 한도 오류 시 남은 공급자로 같은 단계와 작업 폴더를 이어간다. 둘 다 사용할 수 없으면 파일을
보존하고 `needs_attention`으로 전환한다. 검토로 전환한 세션은 기존 검토자 권한과 응답 검증을 유지한다.

새 개인 하네스 터미널은 아직 이 자동 협업 흐름에 연결하지 않았다. 대화형 터미널이 잠잠해졌다는 사실만으로
작업 완료나 다음 단계 전달을 판단하면 승인 대기·사용량 소진·계속 생각 중인 상태를 혼동한다.
다음 구현은 이 경계를 명시적인 실행 이벤트로 연결한다.

1. **실행 프로필**: 공급자, 진입 명령, 설정 상속 방식, 지원 기능(구조화된 결과, 취소, 승인, 이어가기)을 묶는다.
   `sy`/`syc` 대화형 실행과 SDK/app-server 실행을 같은 것으로 가장하지 않는다.
2. **동료 레지스트리**: 동료 ID와 실제 CLI 세션 ID, 프로세스, 작업 폴더의 대응을 저장한다. 복제·재시작은 새
   실행 ID로 기록한다. 여러 동료가 같은 폴더에 있어도 최근 세션이라는 이유만으로 입력을 보내지 않는다.
3. **업무와 결과**: `Task { id, dependencies, assignee, role, workspace, status }`,
   `Result { taskId, agentId, summary, changes, checks, unresolved }`를 저장한다. 구현자·검토자 권한을 별도로 적용한다.
4. **메시지함**: 송신자·수신자·업무 ID·중복 방지 ID를 가진 메시지를 저장하고 `queued → delivered → acknowledged`
   상태를 추적한다. 이미 실행 중인 턴에는 입력을 끼워 넣지 않고 다음 턴에 전달한다.
5. **스케줄러**: 결과 이벤트가 도착한 업무만 후속 업무를 연다. 한도 소진 시 진행 요약·변경 파일·남은 업무를
   넘기며, 계정 한도는 모델만 바꿔 재시도하지 않는다. 취소는 후속 업무와 대기 메시지에도 전파한다.

## 협업 방식별 차이

- 순차 협업: 구현 → 검토 → 수정으로 시작한다. 한 번에 한 동료가 수정 권한을 가진다. 기존 자동 협업의 동작과
  회귀 테스트를 재사용할 수 있다.
- 병렬 협업: 독립 업무만 동시에 실행한다. 저장소 또는 worktree별 수정 책임을 나누고, 공유 폴더 동시 수정을
  허용하기 전에 소유권·충돌 처리·통합 검증을 정의한다. 모든 필수 업무와 통합 검증이 끝나야 전체 완료다.

협업 방식은 사용자에게 선택을 요청한 상태다. 이 문서는 위 확장의 설계이며, 메시지함·병렬 스케줄러·개인 하네스의
자동 한도 전환까지 구현됐다는 뜻은 아니다.

## 검증

생성 진입점은 실제 PTY로 프롬프트 인용과 중복 생성 방지, 인증·폴더 범위, 종료 후 목록 제거를 검사한다.
화면은 데스크톱과 모바일에서 개인 하네스 선택, 시작, 숨기기, 새로고침 후 재연결, 종료를 검증한다.
협업 확장에서는 중복 메시지, 세션 오연결, 실행 중 전달, 수정 충돌, 한도 소진과 취소 전파를 필수 회귀 사례로 삼는다.
