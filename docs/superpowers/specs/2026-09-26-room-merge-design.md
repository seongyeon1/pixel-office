# 한 프로젝트가 여러 방으로 갈라지는 문제 — 설계

## 관측한 갈라짐 (실제 로컬 기록)

| 방 | 실제 관계 | 원인 |
|---|---|---|
| `langconnect` / `langconnect/repo-access-request` | 상위 폴더(비 git)와 그 안의 저장소 `langconnect-enterprise` | 상위 폴더에서 연 세션이 따로 방이 됨. 저장소 방 이름이 폴더 이름이라 알아보기 어려움 |
| `skt/c-agent/wt-eval-console` + `…/apps/web` | 지워진 워크트리. 저장소는 형제 폴더 `skt/c-agent/c-agent` | “가장 가까운 살아 있는 상위 폴더” 규칙이 형제 저장소를 못 찾음. 하위 폴더도 따로 방 |
| `skt` / `skt/docs` | 비 git 폴더와 그 하위 | 비 git 폴더는 세션을 연 폴더마다 방 |
| `pixel-smoke-*` | 앱 스모크 테스트의 임시 저장소, 자동 세션만 있음 | 자동 세션도 방을 만듦 |

## 자동 규칙

1. **지워진 워크트리 복원.** `cwd`가 없으면, 살아 있는 가장 가까운 상위 폴더와 그 **바로 아래 폴더**(형제 저장소 후보),
   그리고 이미 확인한 저장소들의 `.git/worktrees/*/gitdir`에서 그 경로를 찾는다. 찾으면 그 저장소의 방,
   브랜치는 `.git/worktrees/<이름>/HEAD`에서 읽는다. `git worktree prune` 뒤에는 찾을 수 없다(그땐 수동 합치기).
2. **비 git 하위 폴더.** git이 아닌 방의 경로가 다른 비 git 방 경로 안에 있으면 바깥 방으로 합친다.
   홈 폴더와 그 위는 합칠 대상이 되지 않는다(모든 폴더가 홈으로 빨려 들어가는 것을 막음). git 저장소 방은 합치지 않는다.
3. **자동 세션만 있는 경로는 방을 만들지 않는다.**
4. **이름.** git 방은 원격 `origin`의 저장소 이름을 함께 보인다(`repo-access-request · langconnect-enterprise`).

## 수동 합치기

- `room_aliases(source, target)`. 합치면 서버가 `/api/observed`의 `projectPath`를 대상 방으로 바꿔 내려주고,
  `/api/projects`에서 원래 방을 뺀다. 맵·오피스·필터·자동 기록이 모두 같은 결과를 본다.
- 체인은 끝까지 따라가고, 자기 자신이나 순환이 되는 합치기는 거절한다.
- 방 머리의 **합치기**에서 대상 방을 고르고, 합쳐진 방에는 “합쳐진 폴더” 칩과 **분리** 버튼이 있다.
- 작업 폴더·터미널·앱 작업은 원래 저장소 경로 그대로다. 합치기는 보이는 묶음만 바꾼다.

## 테스트

- vitest: 형제 저장소의 워크트리 기록으로 복원, 비 git 하위 폴더 합치기와 홈 제외, 자동 전용 경로, 원격 이름,
  별칭 저장·체인·순환 거절, API.
- e2e: 한 방을 다른 방으로 합치면 동료가 옮겨 가고, 분리하면 돌아온다.
