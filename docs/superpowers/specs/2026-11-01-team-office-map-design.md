# 팀 오피스 맵 — 설계

작성일: 2026-11-01 · 상태: 초안(사용자 승인 대기)

## 왜

Slack 코디네이터 작업(PR #14)으로 "동료"(코디네이터 + 폴더별 동료)가 생겼지만, 동료는 설정 화면 명단에만 있다. 오피스의 전체 맵(`ProjectMap` → `FloorMap`)은 여전히 컴퓨터에서 감지한 Claude/Codex 세션을 저장소(폴더) 방에 앉힐 뿐이라, "우리 팀이 누구고 지금 무슨 일을 하고 있나"가 보이지 않는다.

사용자가 원하는 것: **맵을 열면 지금 돌아가는 일 전체가 한눈에 보이는 것.** 일마다 두 가지가 같이 보여야 한다.

- **맡은 일** — 사람이 맡긴 일의 제목 ("회의록으로 Jira 티켓 정리")
- **지금 동작** — 그 순간 하고 있는 일 ("README.md 읽는 중", "Jira 발급 승인 대기")

사용자는 전체 맵을 "아예 새로 싹" 바꿔도 된다고 했다.

## 정해진 모습 (사용자 확인)

브레인스토밍에서 시안 A(말풍선)·B(맵 + 진행 보드)·C(동료별 방 + 팻말)를 보여 줬고, 사용자는 **B와 C를 합친 시안**을 골랐다. 시안 파일: `.superpowers/brainstorm/81713-1793485392/content/map-hybrid.html`.

### 화면 구성

전체 맵 화면(`view === 'overview'`)을 두 영역으로 나눈다.

**왼쪽 — 오피스 맵 (C)**
- 등록된 동료 한 명 = 방 하나. 방 이름은 동료 이름.
- 방 문 앞 **팻말**에 그 방에서 돌아가는 일마다 "맡은 일 + 지금 동작"을 적는다. 일이 여럿이면 팻말도 여러 장.
- 할 일이 없는 동료의 방은 어둡게(쉬는 중).
- 코디네이터는 입구의 **안내 데스크**에 앉는다. 코디네이터가 Slack 요청을 처리 중이면 데스크에 "요청 N건 배정 · 계획 세우는 중" 같은 상태가 보인다.
- 동료로 등록되지 않은 폴더에서 돌아가는 세션은 **복도**에 보인다.

**오른쪽 — "지금 진행 중" 보드 (B)**
- 진행 중인 일을 한 줄씩. 줄 = 맡은 일 제목 + 출처 배지 + 담당(동료/복도) + 지금 동작.
- **승인 필요**(질문·승인 대기) 묶음이 맨 위, 그다음 진행 중.
- 출처 배지: `Slack` / `오피스` / `터미널`.
- 줄을 고르면(마우스 올림/선택) 해당 방이 강조된다. 방이나 팻말을 고르면 보드의 해당 줄이 강조된다.

### 누가 어디에 보이나 (사용자 확인)

| 일의 출처 | 보이는 곳 |
|---|---|
| Slack으로 맡긴 일(코디네이터 배정 또는 채널 바인딩) | 맡은 동료의 방 |
| 오피스에서 맡긴 일(앱 run) | 그 폴더를 맡은 동료의 방 |
| 터미널에서 직접 연 Claude/Codex 세션 | 그 폴더(또는 하위 폴더)를 맡은 동료의 방 |
| 동료가 없는 폴더의 세션 | 그 저장소의 **임시 방** |

**임시 방 (사용자 결정, 브레인스토밍 시안의 "복도"를 대체)**: 동료로 등록하지 않은 저장소도 지금처럼 방을 하나씩 갖되, 흐린 "임시 방"으로 보인다. 방에 **[동료로 등록]** 버튼이 있어 누르면 그 폴더로 동료 만들기 폼이 열리고, 저장하면 정식 동료 방이 된다. 기존 부서 묶음과 방 합치기/나누기(aliases)는 임시 방에 그대로 적용된다(사용자가 지금 쓰는 정리 방식을 잃지 않게). 동료 방도 부서 구역 안에 배치한다.

**배치 규칙 (설계자 판단)**
1. run에 `coworkerId`가 있으면 그 동료의 방이 먼저다(Slack run은 worktree 경로에서 돌 수 있어 폴더로는 못 찾는다).
2. 없으면 폴더로 찾는다. 세션의 `projectPath`(worktree면 메인 저장소 경로)가 동료 폴더와 같거나 그 하위면 매칭하고, 여러 동료가 겹치면 가장 깊은 폴더가 이긴다. 지금 서버의 `coworkers.forFolder`는 정확히 같은 경로만 찾으므로, 이 매칭 함수를 `src/shared/`에 두고 클라이언트와 서버가 같이 쓴다. 서버 쪽 동작(규칙 강제, Slack 배정)은 이번에 바꾸지 않는다.
3. 둘 다 아니면 복도.

**한 일 = 한 줄 (설계자 판단)**: 앱 run과 그 run이 띄운 관리 세션(`ObservedSession.managed.runId`)은 같은 일이다. run이 있으면 run이 줄의 주인(제목·출처), 세션은 "지금 동작"만 제공한다. 코디네이터가 Slack 요청 하나를 여러 동료에게 나눠 주면 배정마다 한 줄(각자의 방), 안내 데스크에는 요청 단위로 보인다. 서브에이전트 세션은 별도 줄이 아니라 부모 줄에 묶는다.

### 동작 (사용자 확인: "그대로 좋아")

- 팻말이나 보드 줄을 누르면 지금처럼 그 세션의 대화/터미널이 열린다(현재 `onOpen(root, worker)` 경로).
- 보드의 승인 대기 줄에서 바로 승인/거절할 수 있다.
- 지금 맵의 픽셀 캐릭터와 움직임(라운지 커피, 퇴근, 자리 비움 흐림, 보고 표시)은 새 방 안에서 그대로 살린다.

## 목표 / 비목표 / 안티골

**목표**
- 맵 한 화면에서 진행 중인 모든 일의 "맡은 일 + 지금 동작"이 읽힌다.
- 동료 명단(설정)과 맵이 같은 팀을 보여 준다.
- 승인이 필요한 일이 가장 먼저 눈에 띈다.

**비목표**
- 동료 설정 화면, Slack 연동 동작 자체는 바꾸지 않는다.
- 새 데이터 저장소나 외부 서비스 연동을 추가하지 않는다.
- 저장소별 상세 오피스(`view === 'office'`, `ObservedOffice`/`TerminalWorkbench`)는 이번 범위가 아니다. 전체 맵에서 들어가는 경로만 유지한다.

**안티골 (기술적으로 돌아가도 실패)**
- 팻말이 "응답 중", "명령 실행" 같은 범주명만 보여 줘서 무슨 일인지 여전히 모르는 상태.
- 일이 5~8개 동시에 돌 때 팻말이 겹치거나 맵이 읽히지 않는 상태.
- 동료를 등록하지 않은 사용자(지금 거의 모든 폴더)에게 맵이 텅 비거나 복도만 길게 늘어지는 상태.

## 데이터에서 필요한 것

- **맡은 일 제목**: 앱 run은 작업 제목, Slack Job은 요청 문장(짧게), 터미널 세션은 첫 요청(`ObservedSession.prompt`/`label`)을 쓴다. 제목이 없으면 "(제목 없음)".
- **지금 동작**: 지금 `ObservedSession`에는 범주(`activity`)와 `attention`만 있고 구체 동작이 없다. 세션 스캐너가 이미 읽는 마지막 이벤트(`ObservedEvent.title`/`detail`, 예: 도구 이름 + 대상 파일)에서 짧은 문장을 만들어 세션에 실어 보내야 한다. 승인/질문 대기는 `attention`으로 "○○ 승인 대기"를 만든다.
  (설계자 판단) 문장은 서버의 세션 감지 쪽에서 만들어 `ObservedSession`에 짧은 선택 필드(예: `action?: string`, 80자 이내)로 싣는다. 앱 run은 자기 관리 세션의 `action`을 쓰고, 세션이 아직 없으면 run 상태 라벨(`statusLabels`)로 대신한다.
- **동료 명단**: `/api/coworkers` (코디네이터 포함).
- **코디네이터 상태** (설계자 판단): 서버의 Slack 연결이 이미 가진 Job 상태에서 "처리 중인 요청 수 + 각 요청의 단계(배정 계획 중 / 동료 작업 중 / 보고 중)"만 읽기 전용으로 내준다. Slack이 연결 안 돼 있으면 데스크는 "Slack 연결 안 됨"을 보여 준다.
- **승인/거절 버튼** (설계자 판단): 앱이 응답할 수 있는 승인(앱 run의 `Interaction`, 기존 승인 API)에만 버튼을 단다. 터미널 세션의 승인 대기는 앱이 대신 답할 수 없으니 "터미널에서 확인" 버튼으로 그 세션을 연다.

## 지금 코드와의 관계 (빌더 참고)

- 전체 맵: `src/client/overview/ProjectMap.tsx` → `src/client/floor/FloorMap.tsx`(방 배치 `layout.ts`, 캐릭터 `FloorWorker.tsx`, 움직임 `choreography.ts`, 출퇴근 `roster.ts`). 방 모델은 `overview/projects.ts`의 `ProjectRoom`(저장소 단위, lane=브랜치/worktree).
- 부서(`/api/departments`, `floor/departments.ts`)와 방 합치기/나누기(aliases)는 저장소 방을 전제로 한다.
- 캐릭터 스프라이트는 `office/workerSprite.ts`.

## 빌더에게 맡기는 것

- 방 배치 알고리즘, 팻말/보드의 정확한 시각 디자인, 모바일 레이아웃(좁은 화면에서는 보드를 맵 위/아래로 쌓는 정도).
- 기존 부서·방 합치기 기능을 새 구조에 어떻게 녹일지(유지, 단순화, 제거) — 단, 제거한다면 설계에 근거를 남긴다.
- "지금 동작" 문장 만드는 규칙(도구별 문구).
