# 레포 오피스 하나로 합치기 — 설계

## 왜 둘이었나

앱이 Claude·Codex를 직접 돌리는 **앱 작업** 화면(캔버스 2인 오피스, 작업 입력, 승인 패널)이 먼저 만들어졌고,
이미 돌고 있는 세션을 읽기 전용으로 보는 **외부 세션** 관측이 나중에 붙으면서 “관측 세션은 앱 실행과 별도
타입·API, 외부 세션에는 취소·승인·재실행을 보내지 않는다”(external-sessions.md)는 경계가 화면까지 갈라놓았다.
전체 맵은 이미 둘을 한 방에 앉힌다(`projectRooms`). 레포 오피스만 토글로 두 화면을 오간다.

## 목표

레포 오피스는 한 화면: 층 평면도 하나에 앱 작업 동료와 외부 세션 동료가 함께 앉고, 누른 동료의 **종류에 맞는**
오른쪽 패널이 열린다. 제어 경계(외부 세션에는 승인·중단 없음)는 그대로 둔다.

## 화면

```
┌ {레포} 오피스 · 근무 N · 응답 필요 N · 보고 N ─────── [팀 구성] ┐
│ 층 평면도 (레포 방: 워크트리 줄 — 외부 세션 + 앱 작업 워크트리 줄) │ 오른쪽 패널
│  회의실 · 탕비실                                                 │  ├ 앱 작업 동료 → 승인·질문 / 활동 / 변경 파일 / 결과 / 중단
├ 새 앱 작업: [작업 내용……] [함께 협업 ▾] [작업 시작]              │  ├ 외부 세션 동료 → 요약 / 작업 내역 / 기록 질문 / 이어서 작업 / 퇴근
├ 진행 단계(구현 → 검토 → 수정) — 앱 작업이 있을 때              │  └ 아무도 안 고름 → 진행 중인 앱 작업 요약 또는 안내
├ 동료 목록(계열별) · 자동 기록 N건 · 직접 퇴근시킨 동료           │
└──────────────────────────────────────────────────────────────┘
```

- 앱 작업 동료는 진행 중인 실행이 있을 때만 앉는다(전체 맵과 같은 규칙). 워크트리 줄은 `pixel/<run>` 브랜치.
  승인·질문이 오면 `?`. 리뷰 단계에서는 구현 담당이 리뷰어 옆에 선다.
- 선택: 캐릭터 또는 목록에서 고른 동료가 오른쪽 패널을 결정한다. 사이드바의 Claude/Codex 버튼은 진행 중인
  앱 작업의 해당 동료를 고른다(없으면 팀 설정 요약).
- 없어지는 것: `외부 세션 N / 앱 작업` 토글, 캔버스 오피스(`Office.tsx`·`draw.ts`), 모바일 2인 선택 줄.
- 팀 구성(직급·모델)은 기존 모달 그대로.

## 구조

1. **분리(동작 변화 없음):** `App.tsx`의 앱 작업 인스펙터를 `AppInspector`로, `ObservedOffice`를
   `SessionInspector`(선택 카드 + 기록/대화 패널)와 `SessionList`(목록·퇴근)로 나눈다.
2. **합치기:** `RepoOffice`가 층(`FloorMap` 오피스 모드, `projectRooms`에 최신 실행 포함), 작업 입력, 단계 표시,
   목록을 배치하고, 선택 상태(`{ kind: 'run', provider } | { kind: 'session', id }`)로 인스펙터를 고른다.
   토글과 캔버스 오피스를 지운다.

## 테스트

- 기존 e2e를 새 화면에 맞춘다: 앱 작업 시작 → `?` 표시된 동료 → 승인 패널, 외부 세션 선택 → 기록·대화·이어가기,
  두 종류가 같은 층에 동시에 보임. 제어 경계: 외부 세션 패널에 승인·중단 버튼이 없다.
- vitest: 선택 상태 → 인스펙터 종류 결정, 실행 동료 좌석(워크트리 줄).
