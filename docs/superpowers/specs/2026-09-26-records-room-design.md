# 자동 기록 작업을 기록실로 분리 — 설계

## 문제

훅이 턴마다 `claude -p`로 업무일지·세션 요약·요약 종합·지식 추출·memory-lake 컴파일을 돌린다. 이 세션들이
사람이 연 세션과 똑같이 맵에 올라와서, 끝나는 즉시 `!` 보고로 뜬다. 최근 36시간 관측 194개 중 대부분이 이런
세션이었고, 관측 상한(최근 200개)을 차지해 사람 세션을 밀어낼 수도 있다.

## 판별

| 공급자 | 자동 세션 신호 | 확인 |
|---|---|---|
| Claude | 기록의 `entrypoint === 'sdk-cli'` (대화형은 `cli`) | 최근 40개 세션에서 예외 없음 |
| Codex | `session_meta.payload.source === 'exec'` 또는 `originator`에 `exec` 포함 | 현재 로컬에 해당 세션 없음 — 규칙만 둔다 |

앱 자신의 작업(`workspaces/`)과 기록 답변(`chat/`)은 이미 관측에서 제외돼 있다.

종류는 프롬프트 첫머리로 나눈다(표시용, 틀려도 “기타 자동 작업”으로 떨어질 뿐 판별에는 영향 없음):
업무일지, 세션 요약, 요약 종합, 지식 추출, memory-lake, 테스트 실행, 기타.

## 동작

- `ObservedSession.automated`. 자동 세션은 레포 방·오피스·근무 인원·`!` 보고·동료 목록·사이드바 집계에서 빠진다.
- 탐색: 이미 자동으로 판별된 파일은 우선순위를 낮춰 관측 상한이 사람 세션부터 채워지게 한다.
- 층에 **기록실**을 둔다. 지금 `active`인 자동 작업만 앉고, 끝나면 사라진다(퇴근 동선 없이).
  기록실 머리말에 “작성 중 N”.
- 사이드바 **기록** 화면: 자동 작업을 날짜 → 레포 → 종류로 묶어 보여주고, 펼치면 마지막 응답(결과 본문)을
  `/api/observed/:id`에서 불러와 보여준다. 종류·레포 필터.
- 레포 오피스 동료 목록 아래 “자동 기록 N건 → 기록에서 보기”.

## 테스트

- vitest: Claude `sdk-cli`/`cli`, Codex `exec` 판별, 자동 세션 탐색 우선순위, 종류 분류,
  방·보고·근무 집계 제외, 기록실 좌석.
- e2e: 자동 세션 픽스처가 방에 안 나타나고 기록실·기록 화면에 나타나며, 결과 본문을 펼쳐 볼 수 있다.
